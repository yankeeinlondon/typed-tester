# Plan: Remove Cache System from typed-tester

## Problem Statement

The current caching system in typed-tester has several issues:

1. **Error Counting Bug**: The test summary shows "No errors!" despite having 49 individual test errors due to cache-related logic inconsistencies between raw TypeScript diagnostics and structured test file diagnostics.

2. **Complexity**: The multi-layered caching system (symbol, source, test caches) adds significant complexity without clear performance benefits for the typical use case.

3. **Maintenance Overhead**: Cache invalidation logic, file hashing, and cross-cache dependencies create maintenance burden and potential bugs.

4. **File System Pollution**: Creates multiple `.ts-*-lookup.json` files in project directories.

## Solution: Complete Cache Removal

Remove the entire caching system and replace with direct, real-time analysis. This will simplify the codebase, eliminate cache-related bugs, and improve maintainability.

### Phase 5: Error Counting Fix (1 hour)

**Root Cause Resolution:**
The current bug occurs because `getTestCacheSummary()` uses `getFileDiagnostics()` (raw TS diagnostics) instead of the structured test file diagnostics stored in cache.

**New Direct Approach:**
```typescript
function calculateTestSummary(testFiles: TestFile[], opt: AsOption<null>): TestSummary {
  let filesWithErrors = 0;
  let testsWithErrors = 0;
  let filesWithWarnings = 0;

  for (const testFile of testFiles) {
    const allDiagnostics = testFile.blocks.flatMap(b => b.diagnostics);
    const errors = allDiagnostics.filter(d => !opt.warn.includes(d.code));
    const warnings = allDiagnostics.filter(d => opt.warn.includes(d.code));
    
    if (errors.length > 0) filesWithErrors++;
    if (warnings.length > 0) filesWithWarnings++;
    testsWithErrors += errors.length;
  }

  return {
    filesWithErrors,
    testsWithErrors,
    filesWithWarnings,
    // ... other summary data
  };
}
```

### Phase 6: Performance Optimization (2-3 hours)

**Potential Performance Concerns:**
- Real-time TypeScript compilation for each run
- Symbol analysis without caching
- File I/O for every command execution

**Mitigation Strategies:**

1. **Lazy Loading and Minimal Analysis**
   ```typescript
   // Only analyze files that are actually needed
   const relevantFiles = filterRelevantFiles(allFiles, command, options);
   ```

2. **In-Memory Project Reuse**
   ```typescript
   // Reuse TypeScript project instance within single command execution
   const project = getProject(); // Singleton pattern
   ```

3. **Parallel Processing**
   ```typescript
   // Process files in parallel where possible
   const results = await Promise.all(files.map(analyzeFile));
   ```

4. **Incremental Analysis**
   ```typescript
   // For commands that don't need full project analysis
   const minimalAnalysis = getQuickDiagnostics(files);
   ```
