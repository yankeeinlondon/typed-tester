# Test Command Counting Improvement

**Date**: 2025-10-23
**Status**: ✅ COMPLETE (All 5 phases)
**Owner**: Claude Code

## Problem Statement

The `test` command currently reports test counts that differ significantly from Vitest's counts, creating confusion for users. For example:

**Current behavior:**

```txt
✓  tests/unit/utils/urlLink.test.ts (26 tests, 232ms, 789μs/line)
```

**Vitest behavior (same file):**

```txt
✓ tests/unit/utils/urlLink.test.ts (13 tests) 3ms
```

### Root Cause

The current implementation appears to be counting each `it` block twice - once for runtime tests and once for type tests, resulting in doubled counts. This creates several issues:

1. **Inconsistent terminology**: The word "tests" means different things in Vitest vs the `test` command
2. **Lack of granularity**: Users can't distinguish between `it` blocks and type assertions
3. **Missing information**: No indication of how many tests actually contain type tests
4. **Timing display issues**: Timing metrics are only shown when thresholds are exceeded, and formatting could be improved

## Proposed Solution

### New Counting System

Introduce three distinct metrics to provide better granularity:

1. **Tests**: Count of `it`/`test` blocks (matches Vitest nomenclature)
2. **Type Tests**: Count of `it` blocks that contain `type cases = [...]` declarations
3. **Assertions**: Count of individual type assertions within `type cases` arrays

### New Output Format

**File line format WITHOUT `--metrics` flag:**

```txt
✓  tests/unit/detection/preferred-language.test.ts (16 tests, 8 type tests, 38 assertions) 34ms
```

**File line format WITH `--metrics/-m` flag:**

```txt
✓  tests/unit/detection/preferred-language.test.ts (16 tests, 8 type tests, 38 assertions) 34ms | 968μs/line
```

### Timing Display Improvements

**Always show milliseconds:**

- Currently: Only shown when threshold exceeded
- New: Always shown for every file

**Color coding:**

- Fast tests (below threshold): Dimmed gray text with reduced font weight
- Slow tests (warning threshold): Orange/yellow text (existing)
- Very slow tests (critical threshold): Red text (existing)

**μs/line metric:**

- Currently: Shown inline with ms, comma-delimited
- New: Only shown with `--metrics/-m` flag
- Separator: ` | ` instead of comma
