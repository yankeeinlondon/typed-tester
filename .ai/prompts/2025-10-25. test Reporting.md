## Bug in Describe Blocks?

The `test` command works well in most cases but I found that when I used on an external repo of mine (`inferred-types`), it produced this output:

```txt
Test Results [ filter: RetainUntil__ ]:
---------------------------------------------
 ⤬  tests/string-literals/sub-strings/RetainUntil__Nested.test.ts (19 tests, 27 type tests, 48 assertions, 8 tests skipped) 955ms
    [ ⇣ ] RetainUntil__Nested<TStr,TFind,TNesting> using new syntax
    [ ⇣ ] retainUntil__Nested(str, find, incl, nesting) using new syntax

TEST SUMMARY:

- 8 of 27 tests had errors
- 1 of 1 test files had errors
- 27 of 27 tests have type assertions (48 total assertions)
- 8 tests were skipped

- use --verbose to get more details
- use --show-passing to show passing tests (not just erroring tests)
```

As you can see from the output:

- I filtered on a single file: `tests/string-literals/sub-strings/RetainUntil__Nested.test.ts`
- It says that two describe blocks were _skipped_ (and that is correct)
- It says nothing about the other two blocks which were NOT SKIPPED!
- Then it says there were 8 tests with errors but it has reported none!
